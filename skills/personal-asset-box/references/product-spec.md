# 个人素材盒产品规范

## 核心任务

用户的主路径是：拖入图片，点选少量标签，保存；以后按标签找到它，并取出原图使用。

收藏动作应尽量只需点选。备注与来源链接选填；没有时间整理时，也允许直接保存到“待整理”。检索围绕“我现在要做什么”展开，而不仅是识别画面内容。

## 第一版范围

| 能力 | 要求 |
| --- | --- |
| 导入 | 拖放、文件选择、多张导入；JPG、PNG、WebP |
| 标签 | 常用标签、最近标签、已有标签补全、新建标签 |
| 保存 | 原图、标签、备注、来源链接；无标签可保存 |
| 查找 | 缩略图；文件名、标签、备注搜索；多标签 AND 筛选 |
| 使用 | 大图预览、修改标签、导出原图 |
| 安全 | 删除确认；不改动来源文件；完整备份与恢复 |

第一版不做登录、云同步、团队协作、视频解析、网页自动抓取、手机 App 或 AI。

## 标签设计

标签优先表达复用意图，可从三类中少量选择，不强制每类都填：

- 用途：封面参考、选题灵感、拍摄参考、排版参考。
- 内容：人物、咖啡馆、桌面、产品。
- 风格：暖色、极简、留白、大字标题。

每张图先选两三个真正有用的标签。输入时优先匹配已有标签，避免出现“封面”“封面图”“封面素材”等近义重复。标签负责筛选，备注记录“为什么收藏”。

## 默认界面

电脑端单页布局：顶部为搜索、导入和备份操作；左侧为待整理、全部素材和标签筛选；中央为缩略图列表；右侧为当前素材详情及标签编辑。小屏幕可改为纵向布局，但不因此引入移动端产品范围。

## 本地存储与备份

默认用 IndexedDB 保存图片 Blob 与元数据。固定数据库名和版本；升级时迁移，不能静默丢数据。

浏览器数据可能因清理网站数据、无痕模式或存储策略而消失。界面应提醒用户保留来源原图并定期导出备份。完整备份可采用包含 base64 图片数据和元数据的 JSON；恢复前验证格式，遇到重复 ID 时采用明确、一致的规则。

## 后续 AI 扩展

仅在用户明确提出时加入。推荐流程为“AI 建议 5 至 8 个标签，用户确认后保存”。优先从已有标签里选；内容、风格和用途建议分清；不确定时少给，不为凑数生成。未确认建议不写入正式标签库。识别失败不应阻塞手动保存。若使用云端识图，必须说明图片会发往哪个服务，并安全管理密钥。
