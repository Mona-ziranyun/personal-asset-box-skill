# 存储与备份规范

仅在修改存储、导入、删除、备份或恢复时阅读。

## 数据记录

一条素材至少包含稳定 ID、原文件 Blob、文件名、MIME 类型、文件大小、创建时间、更新时间、标签数组、备注和来源链接。新增字段应有缺省值，旧记录读取失败时给出可恢复错误，不能静默丢弃。

## IndexedDB

- 固定数据库名、对象仓库名和整数版本。
- 只在 `onupgradeneeded` 中做版本迁移；迁移必须从旧版本向前兼容。
- 成功提示必须发生在事务 `complete` 之后；同时处理 `error` 和 `abort`。
- 修改界面或筛选逻辑不得清空数据库。
- Object URL 仅用于当前页面预览；素材仍以 Blob 保存，并在不再使用时释放 URL。

## 导入

允许 JPG、PNG、WebP，多文件导入逐一验证 MIME。文件名只用于显示和导出，不能作为唯一 ID。失败时说明是格式、容量还是数据库错误；部分成功时明确成功与失败数量。

默认导入即写入待整理，避免标签步骤阻塞收藏。若改成“确认后保存”，必须保护尚未保存的选择并允许跳过标签。

## 完整备份

备份必须同时包含图片字节和全部元数据。JSON 方案可把 Blob 转为 data URL；若素材量较大，可换成 ZIP 加 manifest，但恢复语义保持一致。

备份顶层包含格式标识、版本、导出时间和素材列表。恢复时先验证格式、版本、必填字段、图片 MIME，再开始写入。明确说明重复 ID 是覆盖、跳过还是生成新 ID；同一次恢复使用一种规则。

## 删除与恢复

删除前显示具体素材名并说明只删除库内副本。来源路径或来源文件从不删除。批量删除需要单独确认范围。

恢复测试必须在独立的空数据库或测试浏览器上下文中完成，避免把验证数据混进用户正式库。
